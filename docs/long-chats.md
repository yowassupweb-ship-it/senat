# Длинные проектные чаты

Обычный путь создания чата из интерфейса использует `reuse_project`: для проекта открывается последний активный чат (закреплённые имеют приоритет). Старые переписки не объединяются и не удаляются. API без этого флага по-прежнему позволяет создать отдельный чат. Архивные чаты не переиспользуются.

## Управление человеком и ассистентом

Под композером всегда доступна кнопка проекта / привязки Git. Она позволяет выбрать существующий проект, компьютер и абсолютный путь к папке. Сервер проверяет папку на указанном компьютере и читает Git. Репозиторий не создаётся автоматически; папка может не содержать Git. Изменение общей папки действует на последующие запуски участников проекта. При смене привязки через эту кнопку или инструмент меняется ключ CLI-сессии, чтобы Codex не продолжил работу в старой папке. Прежние сообщения сохраняются, свежий запуск получает сводку и ограниченную выдержку истории.

Инструменты доступны всем провайдерам через существующий MCP-мост:

- `senate_workspace`: `status` показывает проект, папку и компьютеры; `bind` принимает `path` и `machine`. Если проект ещё не привязан — `senate_attach`; создание проекта остаётся в рамках существующих прав `senate_project_create`.
- `senate_chat_context`: `status`, `configure` с `auto`, `compact` с `instructions`, `history` с курсором `before`. Запрос ассистента на сжатие выполняется после успешного окончания текущего ответа.
- Существующие `senate_preview`, `senate_obligations` и инструменты коллег перечислены в инструкциях управления. Краткая подсказка добавляется и к продолжениям существующих чатов.

Верхняя шкала показывает максимальное известное заполнение среди участников. Раскрытие показывает объём каждого, переключатель автосжатия и кнопку ручного сжатия с пожеланиями к сводке. Отсутствие телеметрии не изображается как 0%. После сжатия отображается ожидание нового измерения.

## Сжатие

По умолчанию включено при 80% известного окна. После успешного обычного ответа создаётся отдельный ход подготовки сводки. Он идёт перед уже ожидающими обычными сообщениями того же участника, сохраняя их порядок. Повторный запрос не создаёт вторую сводку, пока первая в очереди или выполняется. Ручная кнопка работает для всех участников; инструмент ассистента — для него самого. `/compact` и `/compact-all` сохранены.

Только успешная непустая сводка сохраняется в `thread.meta.compact[agent]`, после чего сбрасывается ссылка на CLI-сессию. Ошибка, остановка и пустой результат не сбрасывают контекст. Неудача не запускает бесконечные повторы. Переписка, вложения и проектные данные не удаляются. Пожелания к сводке, цели, решения, пути, результаты проверок и открытые задачи передаются новому ходу. Сводка неизбежно сокращает детали: старые сообщения доступны через `history` и загрузку ранних страниц.

Для нового процесса без CLI-контекста используется сводка и последние сообщения после неё: до 100 сообщений, до 6000 символов каждого и до 60000 символов суммарно. Полная история остаётся в базе. Курсор пагинации учитывает и время, и id, чтобы не пропускать сообщения с одинаковым временем.

Claude/Kimi используют имеющуюся телеметрию. Codex читает последнее `token_count` только из файла своей CLI-сессии (последние 2 МиБ); используются `last_token_usage` и `model_context_window`, а не сумма токенов за весь ход. Если окно недоступно, процент и автосжатие по порогу недоступны; ручное сжатие работает. Встроенное сжатие самого CLI не отключается.

## Проверка

Проверяются порог и отсутствие метрик, отключение автосжатия, дедупликация, приоритет перед очередью пользователя, сохранение истории, отложенный запрос инструментом, курсор одинаковых времён, телеметрия Codex. API-тесты проверяют повторное открытие проектного чата, валидацию папки, настройки и сохранение/сброс CLI-контекста при успехе/остановке. Playwright проверяет шкалу, переключатель, ручной compact, привязку папки, сохранность сообщения и мобильную ширину.

## Машины, файлы и оборудование

В боковом меню открытого чата есть «Папка проекта». В файловой панели доступна настройка папки и компьютера, выбор папки через существующий FolderPicker и список активных участников проекта с их последним действием. `/api/live` содержит `workspace`: проект, machine, path и признак захваченного места работающей сессии. Изменение привязки не переносит запущенный процесс; панель сохраняет его прежнее место. Данные показывают последнюю телеметрию инструмента, а не блокировку конкретного файла.

`workspace_locations:<project>` хранит отдельный путь на каждый компьютер, включая ноду (`machine=""`). Переключение компьютера подставляет сохранённый путь или очищает поле. Файлы не копируются и Git-ветки не синхронизируются автоматически. Смена корня/компьютера пересоздаёт файловое дерево, исключая показ кэша прежней папки.

`senate_workspace status` возвращает известные расположения и машины; `tree` и `read` выполняются через RPC на компьютере проекта и ограничены его корнем. `senate_equipment` показывает назначенные MCP и недостающие параметры без секретов. Доступность MCP зависит от компьютера исполнения; назначенный сервер не считается проверенным только потому, что присутствует в списке.

В подключённом рабочем Senate дополнены назначения существующих MCP: архитектору Context7/Fetch/Playwright, дизайнеру Context7/Fetch, второму разработчику Fetch, редактору и специалисту по рассылкам Firecrawl, специалисту по рассылкам и SEO Playwright, ассистенту Firecrawl. Прежние назначения сохранены, кроме недоступного Fetch у серверных аналитика и ассистента: вместо него назначен проверенный Firecrawl. Context7, Playwright, Firecrawl и «Офис Шара» прошли initialize/tools-list на ноде. Fetch на ноде не работает из-за отсутствующего uvx; новые назначения Fetch сделаны только локальным специалистам. Запущенные сессии получают обновлённое оборудование со следующего запуска.

Fetch также прошёл initialize/tools-list локально на VADER: доступен инструмент `fetch`.
