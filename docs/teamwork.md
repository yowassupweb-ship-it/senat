# Совместная работа

В задачах можно выбрать все входящие зависимости и независимого проверяющего. Зависимости принадлежат одному проекту, сохраняются после смены статуса и должны завершиться успешно. Отмена входящей задачи блокирует продолжение; человек может явно изменить список зависимостей. Циклы отклоняются. Старые одиночные зависимости переносятся миграцией 13.

Исполнитель передаёт результат в `review` с `outcome` и `evidence`. При назначенном проверяющем основания обязательны. Проверяющий получает один автоматический запуск на каждую передачу результата: принимает его с основаниями проверки либо возвращает в `accepted` с замечаниями в `note`. Исполнитель не может принять собственную работу. Если проверяющий не вынес решения, причина показывается человеку; бесконечных повторных запусков нет. Повторная приёмка после доработки запускает новую проверку. Человек сохраняет возможность принять результат.

Вызов коллеги дополняется целью, ограничениями и принятыми решениями проекта, открытыми задачами инициатора и ссылками на версии материалов. Поручения получают результаты всех входящих задач. Пакет ограничен восемью задачами и восемью материалами; это ссылки для дальнейшего чтения, не полная копия проекта.

`senate_artifact_read` возвращает актуальную версию материала. Для обновления через `senate_artifact_save` обязателен `expected_version`. Устаревшее сохранение отклоняется, материал нужно перечитать и согласовать изменения. Проверка действует для артефактов Senate; обычные файлы не являются этими артефактами.

Сессии Senate в одной или вложенных общих папках выполняются последовательно. Разные папки и компьютеры могут работать параллельно. Занятая папка фиксируется при захвате сессии. Синхронный вопрос коллеге из общей папки сразу возвращает статус очереди, чтобы инициатор не удерживал папку в ожидании. Ответ приходит отдельным ходом. Это очередь выполнения, а не Git worktree: внешние редакторы и запущенные вне Senate процессы она не блокирует. Удалённые пути сравниваются по нормализованному имени; символьные ссылки на удалённой машине не разрешаются.

Срочные записки повторяются на следующем вызове инструмента Senate или в следующем ходе до `senate_acknowledge_note`. `senate_inbox` различает `delivered` и `acknowledged`. Подтвердить записку может только её получатель. CLI-процессы не поддерживают единый механизм внедрения сообщений в произвольный момент: принудительное прерывание терминальной команды здесь не добавлено.

На странице проекта показаны исполнители, входящие ожидания, число непосредственно зависимых задач, проверяющие и загрузка команды. Из строки можно открыть задачу. Обновления статусов не перезаписывают несохранённые требования проекта.

Проверки: `cargo test -p senate-core`, `cargo test -p senate-node --test e2e`, `npm run check`, `npm run build`, `npx playwright test tests/teamwork.spec.ts`. Серверные сценарии используют mock, реальные платные модели не запускаются.

## Результат проверки изменений

- Rust: 55 проверок senate-core и 9 интеграционных проверок senate-node прошли. Один сценарий с реальной Claude намеренно отключён.
- Svelte: ошибок и предупреждений нет. Проверка правил дизайна и production-сборка прошли.
- Playwright: 10/16 прошли, включая все 3 новых сценария командной работы. Шесть сценариев в существующем interface.spec.ts не прошли: пять ожидают старый заголовок «Над чем работаем?» вместо текущего приветствия, один ожидает отсутствующее поле «Токен». Эти сценарии не менялись в рамках задачи.
- Новый экран просмотрен в светлой и тёмной темах, включая ширину 414 px.
